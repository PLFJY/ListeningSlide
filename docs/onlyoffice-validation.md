# 验证记录

默认及唯一放映路径为官方 ONLYOFFICE 10.0.0 x2t → PPTY → SDKJS。

## 无窗口检查

- `pnpm test`：27 项核心逻辑单元测试，覆盖裁剪边界、XML/关系读取、音频资源复用、手势、命中检测、归档安全和转换队列。
- `pnpm run build`：检查 TypeScript 并构建网页、Electron 主进程及 preload，启用 noUnusedLocals / noUnusedParameters。

浏览器和 Electron 窗口自动测试、相关依赖及 CI 步骤已删除。界面与放映交互交给人工测试。

## 人工检查参考

运行 `pnpm run dev` 后，可检查：

- 主页右下角作者按钮、作者介绍和 ONLYOFFICE 许可，关闭及重新打开弹窗。作者内容在 `src/author.ts` 编辑，可留空或填写多行纯文本。
- 打开真实课件，检查排版、带进入动画的对象初始隐藏，以及点击、方向键、侧边按钮、手势和滚轮推进动画后再翻页。
- 连续滚轮可以完成当前动画，不额外跳过下一步；反向操作、全屏、关闭和重新打开课件正常。
- 音频图标、播放暂停、裁剪、进度、快退、倍速、A–B 循环及跨页固定正常。

## 已有验证范围

2026-10-21 清理前，macOS ARM64 已用本地 37 MB / 39 页真实课件检查转换及放映，第 16 页检查过逐步显示底部段落和答案。私有课件不纳入源码仓库。此前 Windows x64 打包应用也曾在 Windows 11 ARM64 仿真环境中完成转换与放映检查；这不代表当前源码已重新通过 Windows 实机验证。

这些记录不能替代对任意课件全部对象、字体和复杂媒体的人工检查。

## 平台边界

- 转换器为来源、版本、哈希可追溯的官方二进制，未完整编译所有 ONLYOFFICE C++ 组件。
- 缺失字体使用随包开放字体替代，复杂字体排版仍需目视检查。
- 已测 Windows 环境有 Microsoft VC++ v14 runtime；当前不附带微软 CRT，未验证缺少该运行库的干净系统。
- Windows x64 在 ARM64 上仿真通过不等于原生 ARM64 Electron 验证。UNC 共享目录启动曾出现 GPU 子进程失败，使用本地副本后通过。
